# Nonclassicality Network

**Live pages:** https://tahmeedhossain.github.io/GEN_GPT_Level/ · **Source:** https://github.com/tahmeedhossain/GEN_GPT_Level

A curated, **signed**, typed theorem graph of quantum foundations, quantum information,
quantum thermodynamics and resource theories — built so that missing knowledge is visible:

- **Positive edges** record possibility/structure theorems (arrowheads →).
- **Negative edges** record impossibility/no-go theorems (flat-bar terminators ⊣):
  forbids, exclusions (X holds iff Y fails), failed implications, hiding relations.
- **No edge means *unsettled***, never "false" — so the open problems can be enumerated mechanically.

Five interactive pages (open `index.html`, or the live Pages site). The current content version is **v2.6** (2026-11-01);
earlier versions stay online unchanged, and `CHANGELOG.md` lists what changed in each.

## Motivation

Three uses drove the design:

1. **Automated research-idea generation.** "No edge = unsettled" makes the open questions a
   queryable set: every gray matrix cell and every missing typed edge is a candidate theorem,
   with four closure routes (compose recorded edges, prove, counterexample, literature pass).
   The thirteen generated propositions on `index.html` were produced exactly this way.
2. **Easy reviewing.** A field review in graph form: one claim = one edge with a verbatim
   statement, references and a provenance status. Checking the review means auditing edges one
   at a time; disputing it means filing an issue against an edge id, not arguing with a
   paragraph. Releases are versioned and each records its gap census, so the review never
   silently decays.
3. **Visualization.** Layered, signed, filterable pages show the field's logical shape at a
   glance — where possibility flows, where no-go bars block — and the witness panels answer
   "what is required, at model / state / process level, to observe effect X?" interactively.

The review process is itself the generator: surveying the field in this format yields its own
research agenda as a by-product.

## Data schema (v2)

Top-level keys of `data/network_v2.json`:

- `nodes`: `{id, type ∈ {axiom, model, state, process, witness, effect, task}, label, def, s?}`
- `edges`: `{id, source, target, kind, status, statement, refs[]}`
  - `kind ∈ {implies, equiv, necessary, not_implies, enables, forbids, hides, generates, subset, pairs, excludes, hosts, witness, open}`
  - `status ∈ {theorem, partial, counterexample, derived, definition, open}` — epistemic provenance
  - polarity is **semantic** and orthogonal to status: `meta.polarity.negative_kinds` lists the no-go kinds
- `witnesses`: per-witness structured records `{requires: {model, state, process}, blind, note?, combos}`
- `combos`: referenced state × process rows with per-witness verdicts `fires / hidden / blind`
- `gaps`: named open problems and derived propositions

**Contributing an edge:** include a precise statement, a reference (or a proof for `derived`),
a kind, a status, and respect the polarity convention. Closing an uncharted matrix cell
(gray in the v2 "Witness algebra" tab) is the canonical contribution.

## Reliability and provenance

- `theorem` edges are literature claims; post-2019 load-bearing results were verified against
  bibliographic sources during curation (Oct 2026). The paper's bibliography was verified
  programmatically against Crossref on 2026-10-23: 58/70 exact matches on volume/page/year;
  the rest are classics Crossref indexes poorly (CHSH 1969, Moyal 1949, ...), kept with their
  standard citations; two records were corrected from publisher metadata (Xu 2024; Jokinen et al. 2024).
- `derived` edges are proved in `catalog/` and in the combined paper; novelty searches for N1, R1, R3, R4
  (2026-10-23) and for U1–U7 (2026-11-01) found no prior statements. They are still not *claimed* as
  firsts; most round 1–3 results are compositions of known theorems or elementary (P1, R1, R2 are folklore-level).
- Round 4 searched the literature *before* each proof: results found there are recorded as `theorem`
  edges with the reference (U5b, U6), i.e. as corrections of the curation, not as new results.
- Scope corrections found when the proofs were written out in full (combined paper, C7–C13) are recorded
  in v2.6 as appended scope notes (D2, R2, N1, GN5, R1, R6) and as a corrected kind (A5); the released
  v2.4 file and pages keep the original records, by the versioning rule.
- Composed corollaries name the exact edges they compose, so each is auditable in one step.
- Corrections welcome as issues/PRs; releases record their gap census.
